# Работа агентов Z-Trader AI

По умолчанию главный агент — [оркестратор](roles/orchestrator.md). [AGENTS.md](../AGENTS.md) задаёт выбор контекста. Сабагент читает только свою назначенную роль: [тестировщик](roles/tester.md), [кодер](roles/coder.md) или [ревьюер](roles/reviewer.md).

## Выбор скилла

Скиллы находятся в `.agents/skills` и доступны в выборе скиллов проекта. В промпте можно указать имя явно:

| Вызов | Назначение |
| --- | --- |
| `$tdd-workflow` | [Полная цепочка](skills/tdd-workflow/SKILL.md): тестировщик → RED → кодер → проверки → ревьюер → финальный хук |
| `$architect` | [Мозговой штурм](skills/architect/SKILL.md) перед реализацией функционала |
| `$researcher` | [Исследование](skills/researcher/SKILL.md) глобальной задачи или её подзадач |

TDD-воркфлоу и архитектор вызываются явно. Исследователь также может выбираться по исследовательской задаче; обычные правки и настройка проекта его не подключают. Полное содержимое скилла загружается только при использовании. Если новый скилл не появился, перезапусти Codex. Механизм обнаружения описан в [официальной документации](https://learn.chatgpt.com/docs/build-skills).

Лимиты исправлений, передача контекста и условия остановки хранятся только в TDD-воркфлоу. Это инструкции работы агентов, а не ОС-изоляция файлов. Уже прочитанное в текущем чате не удаляется: для чистого контекста нужен новый чат, а сабагенты запускаются без наследования истории.

## Планы и сохранение контекста

Остаются ровно два входных плана: [глобальный](plans/global.md) для общей задачи и [диапазоны](plans/range-detection.md) для детектора. Читай только выбранный план и дополнительные документы по указанной необходимости. Для обычной локальной задачи исследовательские планы не нужны.

## Проверки

`pnpm typecheck` проверяет TypeScript, `pnpm lint` — ESLint, `pnpm test:unit` — Vitest, `pnpm test:e2e` — Playwright. `pnpm test:all` объединяет все уровни тестов. Новый уровень тестирования нужно добавить в эту команду.

`pnpm check` выполняет TypeScript → линтер → все тесты и останавливается при ошибке. Его вызывает `.husky/pre-commit`, а оркестратор — в конце успешного TDD-воркфлоу без создания коммита. E2E сначала собирает приложение, затем запускает собственный production-сервер на порту 3100; открытый dev-сервер не используется. Для E2E нужен браузер Playwright; установка: `pnpm exec playwright install chromium`.

В цепочке все проверки запускает оркестратор. Он передаёт кодеру описание нарушения контракта без исходников тестов. Коммит автоматически не создаётся.
