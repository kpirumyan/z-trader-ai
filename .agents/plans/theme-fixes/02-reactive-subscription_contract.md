# Контракт 02: Реактивная подписка на тему через useSyncExternalStore

- **Идентификатор контракта:** `02-reactive-subscription_contract.md`
- **Связанный пункт аудита:** Пункт 2 (`theme-system_review.md`)
- **Статус:** `APPROVED` (Архитектурная спецификация)

---

## 1. Архитектура и инварианты (System Architecture & Invariants)

1. **Реактивность без React Context:**
   Для оповещения компонентов об изменении темы используется стандартный хук `useSyncExternalStore`. Запрещено внедрять корневой `React.createContext`, так как это приводит к каскадным ререндерам всего дерева терминала.
2. **Нулевой оверхед по ререндерам (0 Re-renders for non-subscribers):**
   Компоненты, которые **не вызывают** `useTheme()` напрямую, не должны ререндериться при смене темы. Их внешний вид обновляется силами движка браузера через каскад CSS-переменных.
3. **Наблюдение за DOM через `MutationObserver`:**
   Внешнее хранилище подписывается на мутации атрибутов элемента `document.documentElement` с фильтром `attributeFilter: ["data-theme"]`.
4. **Гидратация и SSR-безопасность:**
   Функция `getServerSnapshot` для `useSyncExternalStore` обязана возвращать консистентное значение `DEFAULT_THEME` (`"dark"`), предотвращая ошибки несоответствия гидратации (hydration mismatch).

## 3. Критерии приемки (Given / When / Then)

### Сценарий 3.1: Точечный ререндер подписанного компонента
- **Given** компонент `A` вызывает `useTheme()`, а компонент `B` не вызывает `useTheme()`
- **When** тема переключается с `"dark"` на `"light"`
- **Then** компонент `A` повторно рендерится с новым значением `theme: "light"`, а компонент `B` **не производит** ререндера Fiber

### Сценарий 3.2: Реакция на внешнюю мутацию DOM
- **Given** подписанный React-компонент смонтирован на странице
- **When** атрибут `document.documentElement.dataset.theme` изменяется внешней функцией или сторонним скриптом
- **Then** `MutationObserver` фиксирует изменение, и подписанный компонент синхронно обновляет свое состояние

### Сценарий 3.3: Корректное освобождение ресурсов (Unmount)
- **Given** подписанный компонент размонтируется
- **When** вызывается функция отписки слушателя `useSyncExternalStore`
- **Then** обработчик отписывается, и `MutationObserver` отключается при отсутствии других активных подписчиков (предотвращение утечек памяти)

### Сценарий 3.4: Серверный рендеринг (SSR)
- **Given** выполнение на сервере (отсутствует объект `window` / `document`)
- **When** вызывается хук `useTheme()`
- **Then** хук возвращает детерминированное состояние на основе `DEFAULT_THEME` (`"dark"`) без падений

## 4. Компромиссы и обоснование (Trade-offs & Rationale)

- **Почему `useSyncExternalStore`, а не `useState` + `useEffect`:**
  `useSyncExternalStore` гарантирует синхронное считывание внешнего состояния DOM без визуального мигания (tearing) при параллельном рендеринге React 18/19 и автоматически интегрируется с внешними источниками событий.
- **Отказ от глобального Context Provider:**
  Торговый терминал содержит множество высокочастотных элементов (тикеры, книга заявок, лента сделок). Использование единого Context для темы спровоцировало бы нежелательные ререндеры сотен тиковых ячеек таблицы при переключении темы.
