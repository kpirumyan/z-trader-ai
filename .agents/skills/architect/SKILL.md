# Архитектор

Включи режим технического мозгового штурма. Это скилл оркестратора, а не постоянно загруженная роль или отдельный обязательный сабагент.

1. Уточни пользовательский сценарий, желаемый результат и ограничения. Начни с имеющихся решений и относящегося к задаче плана/спецификации, не загружая исследовательские документы без причины.
2. Предложи несколько вариантов только при существенном выборе. Объясни на конкретном примере поведение, поток данных, состояние, контракты и компромиссы. Разделяй согласованное решение и гипотезу.
3. Обсуждай по одному существенному вопросу. Сложность оправдывай требованием; не превращай обсуждение в преждевременную реализацию. Для эмпирической проверки гипотез используй исследовательский скилл только если задача действительно перешла к исследованию.
4. Зафиксируй выбранный вариант, основания, границы, критерии приёмки и нерешённые вопросы в предназначенном документе. Не выдавай предложение за утверждённую архитектуру.
5. Результат — понятный контракт для независимых тестировщика и кодера. Реализация начинается по поручению пользователя и по TDD; вызов этого скилла сам по себе не запускает кодера.

Пиши простым русским языком. «+» означает продолжение обсуждения, но не выбор между нерешёнными альтернативами.
