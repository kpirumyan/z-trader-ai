# Отложенные сценарии рабочего места

`terminal-workspace.spec.ts` сохраняет три будущих сценария восстановления из прежнего `tests/e2e/home.spec.ts`. Playwright выбирает `tests/e2e`; эта папка в активный набор не входит. `skip`, `todo`, исключения в конфиге и отдельные команды не используются.

## Активированные группы

| Группа | Активное покрытие |
| --- | --- |
| Исходный HTML оболочки, тема, брендовые изображения | `tests/e2e/terminal-shell.spec.ts` |
| Создание одного пустого workspace, сохранение id, чтение записи, отказы доступа | `tests/e2e/terminal-workspace.spec.ts` |
| Инструкция после клиентского чтения; первый вход и reload | Дополнены существующие сценарии создания и восстановления валидного пустого workspace в `terminal-workspace.spec.ts`; до клиентского JS обе строки отсутствуют |
| Инструкция до PNG и шрифтов; зазор, перенос, стабильность геометрии | Объединено с восемью существующими сценариями оболочки в `terminal-shell.spec.ts`: обе темы × 1440/320px × первый вход/reload |
| Geist, веса 400/600 и цвета, отсутствие кнопок/рамок внутри инструкции | Два сценария обеих тем в `terminal-workspace.spec.ts` |
| Отказ PNG сохраняет инструкцию и доступность New | Два сценария обеих тем в `terminal-workspace.spec.ts` |
| Пояснение New, клавиатура, удержание и возврат фокуса, Escape/Close, сохранность workspace | Сценарий `New explains the next stage, traps focus and closes without changing workspace` в `terminal-workspace.spec.ts` |
| Повреждённая запись не вызывает ложную инструкцию | Дополнены три активных сценария corrupted workspace: malformed JSON, invalid envelope, unsupported version; первый вход/reload |

Группы третьего пункта T1.5 активированы по контракту v1 для TDD. Этот документ фиксирует перенос сценариев; RED/GREEN и проверки выполняет оркестратор.

## Когда возвращать оставшиеся сценарии

| Группа | Условие активации |
| --- | --- |
| Повреждённая запись сохраняется до Start empty | Четвёртый пункт T1.5: объяснение ошибки и действия восстановления |
| Retry повторно читает исправленную запись | Четвёртый пункт T1.5: повторное чтение без автоматической перезаписи |
| Недоступное хранилище оставляет инструкцию и предупреждает о несохранении | Четвёртый пункт T1.5: предупреждение unavailable |

Отсутствие аварии при getter/getItem/setItem и сохранность повреждённой записи уже покрыты активным набором; в deferred остаются проверки будущих действий и предупреждения.

## Дедупликация и измерения

Отдельные отложенные тесты первого входа и клиентской инструкции объединены с существующими тестами публичного storage API. Отдельные восемь сценариев геометрии инструкции объединены с существующей матрицей оболочки. Геометрия панели и watermark измеряется до клиентского JS, затем после появления инструкции при удерживаемых PNG/шрифтах, после PNG и после шрифтов. Измерение текста начинается до `document.fonts.ready`; на 320px проверяются перенос и доступность всего текста в viewport. Прозрачные поля PNG допускается кадрировать: зазор сравнивается с видимым низом рисунка с учётом `object-fit` и overflow предков.

Самостоятельные проверки темы остаются в наборе оболочки. В сценариях workspace переключение темы проверяет сохранение инструкции и доступности управления. Сценарий New проверяет диалог-пояснение текущего этапа; создание окон остаётся будущим поведением.

## Основания выбора API

Публичные роли и текст проверяются локаторами Playwright [Locators](https://playwright.dev/docs/locators), ожидаемые состояния и фокус — [Assertions](https://playwright.dev/docs/test-assertions), задержка и отказ сетевых ресурсов — [Network](https://playwright.dev/docs/network). Проверки используют наблюдаемый DOM, публичный localStorage и геометрию браузера; исходники реализации не нужны.
